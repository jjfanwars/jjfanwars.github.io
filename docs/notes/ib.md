# IB Study (`ib/`)

Private study app for the owner's IB textbooks (not a game). Live at /ib/ (noindex, password).

- **Content is not in the repo.** Book pages (Markdown + scans) and the question bank live in the relay's `IB` Durable Object (SQLite tables `page`, `img`, `kv` with keys `books`, `qs`, `prog`). The repo only has the app (`ib/index.html`) and the build script (`ib/build.py`).
- **Relay (`relay/worker.js`, `ibRoute` + class `IB`):** POST text/plain JSON `{pass, ...}` to `/ib/login|books|page|pages|search|qs|sync|ask`; scans via GET `/ib/img?b=&n=&t=<pass>`; uploads via `/ib/put?t=page|img|kv` with header `x-ib-admin`. Secrets: `IB_PASS` (app password), `IB_ADMIN` (uploads), Anthropic key reused from `ANTHROPIC_KEY` or the Legal DO. `IB_CAP` = Claude replies per day (default 300).
- **Claude:** `/ib/ask` calls `claude-sonnet-5-5` (server-side refusal fallback on, effort medium for marking, low for chat). System = tutor prompt + book contents (fixed, cached), rubric (marking), textbook extracts, with a cache breakpoint on the last system block and top-level automatic caching for the conversation. First chat turn sets `find` (tf-idf page ranking in the DO, `find` op); the client then sends the returned `pages` back on later turns so the prefix stays identical and the cache hits.
- **Pipeline for a new book:** download the PDF, `pdftoppm -r 100 -jpeg -jpegopt quality=62 book.pdf img/p`, have Haiku agents transcribe each page image to `md/NNN.md` (spec: first line `<!-- p:BOOKPAGE -->`, numbered headings `#`/`##`, callouts `> [!keyterm] Term`, `[!case]`, `[!activity]`, `[!questions]`, figures as `*[Figure: ...]*`), then `IB_ADMIN=... IB_PASS=... python3 ib/build.py ID "Title" Subject md img --upload [--imgs]`. build.py makes the TOC, key terms and questions (Paper 2 lists, Paper 1 source sets with 3/4/8/10 marks, activities) and merges into the shared `books`/`qs` lists.
- **App:** Library (TOC, Text/Scan toggle, search, "Ask Claude about this page"), Practice (filters, timer, draft autosave `ib-d-<id>`, Claude marking JSON -> feedback card, follow-up chat, past attempts), Key terms (Leitner flashcards), Progress (weakest topics). Progress syncs to the relay (`sync`), merged by attempt time.
- Books so far: `glopo` Global Politics Course Companion (Oxford 2024), 260 pages.
- **Tutor prompt (`IB_SYS`):** teacher persona: intuition and analogy first, small steps, quick application questions, misconception fixing, memory hooks, cites pages. Library has "Teach me this section" (lesson over the section's pages) and "Ask about this page"; header "Ask Claude" is a general tutor (page finding on).
- **Planner tab:** items in DO kv `plan` (`{id, kind: class|homework|exam|event|task, title, subject, date, time?, end?, rep?: 'weekly', until?, done?, notes?}`), saved whole via `/ib/plan`. Month/week/agenda views, Due list with tick-off, exam countdowns, subject colours by hash. Planner assistant = `/ib/agent` (`planAgent`): Sonnet with tools list_items/add_item/update_item/delete_item looped server-side (max 8 steps), gets a 21-day snapshot and the client's local date/time/timezone. Phone sync: `/ib/cal.ics?t=<pass>` ICS feed (weekly RRULE).
- **Scanned books with no text layer (Chemistry HL, 1062 pages):** `ib/ocr.py SPEC.txt ocr_img_dir md_dir --workers 10` sends each page image (130 dpi grey) to the relay's admin `/ib/ocr` (Claude Haiku 5.5, spec cached) and writes `NNNN.md`. Chemistry spec: LaTeX in `$...$`/`$$...$$`, mhchem `\ce{}`, callouts `[!worked]`, `[!exercise]`, `[!challenge]`, `[!practice]`, `[!nos]`, `[!link]`. Build with `IB_MATH=1 IB_FILE=1` so the app renders KaTeX for that book (books without `math` keep `$` as money).
- **PDF download:** `ib/upfile.py BOOK file.pdf "Name.pdf"` stores the PDF as ~1.9 MB chunks (`fchunk` table, `file:<book>` kv); GET `/ib/file?b=&t=<pass>` streams it back (FixedLengthStream). Book meta `file: true` shows the ⤓ PDF link.
- **Marking** uses structured outputs (`MARK_SCHEMA`) so feedback with LaTeX backslashes is always valid JSON. Chemistry kinds: mcq (1 mark), exercise, challenge, structured (practice papers, marks from `[n]`), marked with a self-written markscheme and ECF.
- The app is also served from a second GitHub Pages site the owner set up (name kept out of this repo). After every app change, sync it yourself: attach that repo with add_repo (the owner can name it), copy `ib/index.html` there as `index.html`, commit and push. Never ask the owner to copy anything.
- **Accounts (Nov 2026):** first name only (`/ib/user {name}` -> `{key, name, tok}`; DO kv `users`). Planner and progress are per account: kv `plan:<key>`, `prog:<key>`; `plan`/`sync`/`agent` need `user`. The first account created copies the pre-account `plan`/`prog`. Calendar feed per account: `/ib/cal.ics?k=<tok>`. Client keeps `ib-user`, `ib-known` (names on this device), and per-account `ib-prog:<key>`, `ib-plan:<key>`, drafts `ib-d-<id>:<key>`.
- **Shell:** left sidebar (Home; Study: Library + pinned books, Practice, Key terms; Organise: Planner, Progress; account at the bottom), bottom tab bar on phones, breadcrumb title, theme toggle (`ib-theme` light/dark/auto, also in the account menu). Hash routes `#/home`, `#/lib`, `#/lib/<book>/<n>`, `#/prac`, `#/q/<id>`, `#/terms`, `#/prog`, `#/plan`, `#/search/<q>` (`setHash` pushes on screen change, replaces on page flips; `route()` on popstate). `shell(t)` = chrome, renderers set their own hash.
- **Library shelf** (`renderShelf`): book cards with reading progress (`prog.lastBy`), pin (`prog.pins`, shown in the sidebar), bookmarks (`prog.marks`, reader bookmark button, also listed at the top of the contents panel). Prefs sync last-write-wins by `prog.pt`.
- **Search box:** type for quick jumps (screens, `p 123`, sections across books, key terms); Enter with nothing highlighted = full-text search.
- **Chat:** streamed with tools (`tutorStream`: server-side tool loop, our own SSE `{t}|{tool,arg}|{err}|{done}`). Tools `read_page` (printed page), `search_book`, `read_screen` (the client's `screen`: open question + draft, flashcard, progress summary). `where()` sends only a one-line `[Location: ...]` note at the start of a message when it changes; no pages are preloaded (keeps usage down). Marking is still a plain JSON call.
- **API key:** `ibKey()` = DO kv `apikey` (set through the one-time page `/ib/key?t=<IB_KEYTOK>`, validated against `/v1/models`) else `ANTHROPIC_KEY` / Legal DO key.
- **Guest mode:** no sign-in needed; without an account everything is stored under `:guest` localStorage keys and nothing syncs (planner assistant needs an account). "Sign in" top right (`signInBox`) creates/opens a name account and merges the guest progress + planner into it. The browser remembers the account (`ib-user`).
- **Study features (Nov 2026):** activity log `prog.days[date] = {m, q, c, p}` (minutes counted while visible + recently active), streak (`activeDay`: 10+ min, a marked question or 10+ cards), week strip on Home, weekly report on Progress (`weekReport`, "Weekly review with Claude"). Mistake log = questions whose latest attempt is under 70%, retry after 2 days (4 after repeated misses), Practice > Mistakes. Highlights/notes: select text in the reader → Highlight / Note / Explain (`selBar`, `prog.hls`, painted by `paintHls`), listed on Progress with "Quiz me on these". "Explain it back" button in the reader. "Plan my day" on Home sends context to the planner agent, which adds study blocks.
- **Past papers (PPP mode):** kv `papers` = `[{id, book, title, session, paper, mins, bounds?: [[7, pct], ...], instr?, qs: [{n, text, marks, kind?, ms? (markscheme), ans? (MCQ letter), topic?}]}]`, served by `/ib/papers`. Practice > Past papers: cover page, timed exam view (Claude hidden), autosave `ib-pp-<id>`, Submit marks MCQs locally and the rest with Claude (3 at a time, markscheme in the rubric when present), grade from `bounds` or `DEF_BOUNDS`; results in `prog.pp`, each answer also saved as an attempt `pp:<paper>:<n>` so misses reach the mistake log. Questions with `ms` in the normal bank are marked against it too. Papers and markschemes will come from the owner; don't source them.
- **Topic mastery map (Progress):** topics = numbered level-2 contents entries (`topicsOf`), grouped by unit. `mastery()` blends best question marks (weight 2, scaled by how many tried), section-review scores (1.5) and flashcard boxes of key terms on those pages (1); untested topics are grey. Tile click = `topicSheet` (Practise filtered by `F.tp`, Read, Teach me). Also a marks-over-time line (rolling average of 5) and an 18-week activity heatmap; hover tooltips via the shared `[data-tip]` handler.
- **Spaced section reviews:** reading 2+ pages of a contents section (level ≤ 3) schedules `prog.rev['book|n']` (`trackSec`). Due checks (1, 7, 30, 90 days; a score under 67% resets) are 3 questions with model answers from `/ib/quiz` (Haiku, structured output, earlier questions passed as `avoid`), self-marked Got it / Partly / Missed. Practice > Section reviews, Home > Today.
- **Reference tab:** formula and data sheet (science books) and case-study bank (Global Politics), from kv `ref:<book>` (`/ib/ref`). Built once with `ib/extract.py BOOK md_dir book.json formulas|cases --upload` (Haiku over each contents section through admin `/ib/gen`, structured output; merges into existing ref). Chemistry: 192 formulas, 80 constants. Global Politics: 327 cases tagged by concept. Page links resolve printed pages via `pagebp`. Run extract.py for each new book.
- **Books (Nov 2026):** `glopo`, `chem`, `phys` (Physics HL, Pearson/Hamper 2023, 599 pages, scanned: Haiku OCR with `phys/SPEC.txt`; topics "A.2 Forces and momentum" + themes, built with `IB_SUBS=1` so unnumbered `##` sub-sections become level-3 contents entries; build.py resolves running-header topic titles by frequency), `math` (Maths AA SL, Oxford 2019, 737 pages, Haiku OCR). Pages the OCR call keeps timing out on: retry from the 100 dpi image, then split the page into top/bottom halves, then tesseract (marked as basic OCR on the page).
- **Maths extras** (owner's zip): `ib/qsets.py` turns transcribed sets with their answer sections into questions with markschemes (`ms`) or practice papers; `ib/addq.py` merges them (replaces by `(book, set)`; `--book` can add a placeholder subject with `pages: 0`, which the app shows as "questions and papers only"; build.py now keeps questions with a `set` when a book is rebuilt). Questions with `ms` show an "Official answer" panel.

## Interactive mind maps (Nov 2026)
- `ib/mindmap.py BOOK MAPID out.json imgs... --upload` reads each mind-map page image with Sonnet (via admin `/ib/ocr`, model param) into a tree `{t, c:[...]}` and stores it as `ref:BOOK.maps[].pages[].tree` (`MM_FROM=k` when the images start at page k). All 18 Maths pages done.
- `mapView` opens pages with a tree as an interactive map: root centre, hubs balanced left/right, tidy tree layout from measured node sizes, SVG curves, pan / wheel / pinch zoom, fold knobs (+N), Recall mode (folded below hubs), Find on map, and a bubble action bar (Explain, Quiz me, Flashcards from the branch via `addCards`, Find in textbook). "Original" shows the drawn page. `S.mm` feeds `where()` (location line + outline as `screen`); `body.mmopen` raises the chat drawer above the map.

## Exam mode, countdowns, study blocks, tagged bank (Nov 2026)
- **Tagged question bank:** questions in kv 'qs' can carry `diff` 1|2|3, `paper` ('1','2','3','1A','1B'), `lvl` 'HL', `calc`, `src:'bank'`. `ib/bank.py add BOOK "Set" files... --upload` imports the owner's banks (.json / .csv / transcribed .md, Claude splits + fills missing tags; replaces the same set); `ib/bank.py retag BOOK --upload` tags questions with no difficulty (all existing books were tagged, Haiku). The owner supplies the banks: don't write questions ourselves. Practice has difficulty / paper / level / source filters and tag chips (`qTags`).
- **Exam mode** (Practice tab "Exam mode", was Past papers): `examHtml`/`wireExam` setup (length, paper, SL/HL, difficulty, topics: all / weakest / chosen), `buildMock` fills ~0.9 marks per minute preferring markschemes, bank questions, untried and weak topics, saves the paper in LS `ib-mocks` and runs it through `openPaper`/`submitPaper` (mock questions keep their original id via `q.qid`, so marks count towards mastery). Results add `breakdown` (marks by topic with Practise buttons, by difficulty); `S.prog.pp` records carry `book` and `mock`.
- **Countdowns:** Home "Exams" strip (`countdownHtml`) from planner items of kind exam (next 60 days), matched to a book by `examBook`; `readiness(B)` = topic mastery (untested = 0) blended 50/50 with the last 3 mock/paper marks (60 days), grade via DEF_BOUNDS once 3+ topics are tested or a paper exists.
- **Study blocks** (`studyBlocks` modal from Home or the planner toolbar): `planBlocks` fills weekday/weekend windows around timed planner items and linked-calendar events, weighting exams by (1 - readiness) and urgency, rotating through weakest topics, with a mock block within 2 days of each exam. Items: kind 'study', `gen:'sb'`, `sb:{b, tp, mock, ex}`; re-running replaces future undone blocks. `openStudy` starts practice / reading / Teach me / a mock.

## Reader upgrade + real diagrams (Nov 2026)
